# Simple RAG chatbot web app

Build a simple RAG chatbot web app with no sign-in or auth. Single shared workspace.

Generated by the Quorq AI SDLC platform from an approved app design.

Every screen here was generated from a design the team reviewed and approved.
A backend was also generated for this project (see `../backend/`), but these
screens still run on **seeded sample data** -- wiring a given screen to a real
endpoint is the next job, not something this repository pretends to have done.

## Approved technology stack

- **Frontend**: Next.js
- **Backend**: FastAPI
- **Database**: PostgreSQL
- **Cloud**: AWS

## Running it

```bash
npm install
npm run dev
```

`npm run build` bundles the app into `out/` as plain static files, and it neither typechecks
nor lints (see `next.config.ts`). The screens were generated, and a generated screen that
renders correctly can still not satisfy `tsc` -- usually an untyped `useState({})` that is
then read for named fields. Deployment would fail on that, which is a poor reason not to
ship a working prototype.

`npm run typecheck` runs `tsc --noEmit` when you want it, and is worth fixing before this
becomes a codebase anyone maintains.

## Checks and tests

- `npm run lint` / `npm run lint:fix` -- ESLint over the whole app; `lint:fix` applies the
  fixes it can. The platform runs `npm run lint` as a gate during development, so keep it green.
- `npm run test` -- Vitest component tests, beside the components they cover.
- `npm run test:e2e` -- Playwright acceptance tests from the `e2e/` folder beside `src/`.
  `npm run test:e2e:install` fetches the browser first. With `E2E_BASE_URL` set it runs against
  that deployed URL; without it, Playwright builds this app, serves `out/` on port 4173 and
  runs against that.

## Layout

- `src/app/` -- the App Router. One `page.tsx` per approved screen, at the screen's own route.
- `src/app/layout.tsx` -- the root layout: the navigation shell every page renders inside.
- `src/lib/ui.tsx`, `src/lib/icons.tsx` -- the component and icon vocabulary
  the screens were written against.
- `src/lib/brand.ts`, `src/index.css` -- the approved brand, as tokens and as
  CSS variables.

## Static export

`next.config.ts` sets `output: "export"`, so this is a static site: no server components, no
route handlers and no server actions. Every page is a client component. Removing that line
turns this back into a server-rendered Next.js app, which then needs a Node host rather than
a CDN.
